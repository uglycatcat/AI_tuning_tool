**本文件夹用于实现一个基于本项目（API_socket）的前端交互工具**
# 背景
1. 该项目只在开发者本地运行，前端作为一种交互手段。
2. 美术风格要求黑白高级风
# 需求
分为两个模式，一个是虚拟PID测试模式，一个是串口调试模式
## 1. 有虚拟PID测试功能，用来调试tuning_tool
该功能暂时作为一个独立功能。
有开始，暂停，重启
目标曲线有三角波，正弦波两种类型。两种信号都有周期，振幅，偏移参数。
当前曲线有PID三个可调参数

### 实现虚拟PID情况下与tuning tool的联动，借助tuning tool调整参数
在虚拟PID内添加一个标识控件，默认为空，表示不接入tuning_tool，点击后翻转为true，表示接入。再次点击可以关闭。但是注意，这个控件被改变后，只在下一次点击重启生效。
重启时如果发现该控件为true那么接入tuning tool。
流程如下，接入后，正常进行计算和图像滚动，但是与此同时以固定频率和总采样时长按照tuning_tool的要求采集相关数据，输出csv文件。然后发送给tuning_tool，与此同时，prompt_concat拼接后的prompt原本输出到output.log的内容现在输出到右上角的prompt文本框中，每次response_parser输出给outpot2.log文件的内容现在输出给右下角的response文本框。
并且需要把response_parser解析出来的pid返回到当前虚拟pid的pid值，从而实现让ai读取当前数据来调整参数。
然后再重复下一轮采集csv数据
（当前tuning_tool测试阶段使用json文件，需要你更改为csv文件）
（需要打开当前所有的边界性限制来进行测试）
目前是测试阶段人为规定进行三轮循环

## 2. 简单的串口调试助手，用来实际接入串口进行调试
有端口号，波特率选项
暂时没有其他需求

## 3. 有PID图像，方便开发者可视化调参效果（虚拟的或者从串口读到的）
- 横轴为时间，默认 **10s** 滚动窗口；按当前模式显示数据源（虚拟仿真 / 串口接入后的数据流）。
- **三条曲线**：目标位置、实际位置、**位置误差** \(e=r-y\)。
- **双纵轴**：左侧为位置量纲（目标、实际）；右侧为**误差**量纲（误差曲线），右轴刻度仅反映 \(e\)。
- 曲线区域上方有**文本统计**（当前误差、窗内平均绝对误差、最大绝对误差、样本点数等），便于快速判断跟踪质量。

## 4. 有文本框可以显示当前发给ai的request的prompt和收到的response给开发者来确认流程是否正确

### 虚拟PID接入tuning_tool的情况

#### prompt框
该文本框会累积显示这一次接入tuning_tool之后，每一次给ai端发送的文本，并且不能被用户修改，只能展示内容。
因为会产生多次prompt，应该有页数标志，可以通过页数直达当次的文本。
每次切换模式或者重启的时候清空

#### response框
该文本框会累积显示这一次接入tuning_tool之后，每一次ai回复后tuning_tool的parser处理后输出的文本，并且不能被用户修改，只能展示内容。
因为会产生多次response，应该有页数标志，可以通过页数直达当次的文本。
每次切换模式或者重启的时候清空

# 页面设计
以从左往右2/3处为左右分界线
以从上往下2/3处为上下分界线
右上方是给ai的输入文本
右下方是ai的输出文本
左下方是虚拟PID模式或者串口模式的控件，还有一个切换模式的按钮，按一下按钮切换成另一个模式的控件，重置页面内容
左上方是曲线图，横坐标是时间，纵坐标是数值，图中包含实际和目标位置，保持滚动。横坐标宽度默认为10s。
